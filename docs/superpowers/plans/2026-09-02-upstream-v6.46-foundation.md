# Upstream v6.46 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish an upstream-identical two-parent baseline and port the fork's approved identity, publication, sandbox, reachability, iteration, and terminal-lifecycle foundations.

**Architecture:** Build from the pinned upstream commit and join history with an `ours` merge. Make narrowly tested adaptations in current upstream sources, retaining release dry runs and upstream runtime ownership while adding internal publication guards and the selected security/lifecycle fixes.

**Tech Stack:** Git worktrees, Node.js 22, TypeScript/CommonJS, Mocha, GitHub Actions YAML, `js-yaml`, Rust/Cargo.

**Spec:** `docs/superpowers/specs/2026-09-02-upstream-v6.46-reconciliation-design.md`

## Global Constraints

- Pin upstream to `e73727662df53bbaf8aad8ba9e489d2c76a79499`, fork tip to `1bc71f6881da82de9f28dc5c78107a9151ed24c0`, and shared base to `3077e372746e3897b3e89dd99dabab20ed7dceb7`.
- The bridge tree must be byte-identical to upstream and report `79 0` against `upstream/main`.
- Preserve upstream package identity and dry-run topology, but guard all public mutation jobs with `github.repository == 'the-open-engine/zeroshot'`.
- Keep Node active; build/test but do not install or activate Rust/native, hosted target, protocol, or Python products.
- Never hand-edit generated `lib/` or protocol projections.
- Do not run a live provider, push, merge shared `main`, publish, or add release credentials.
- After Task 1 creates the sibling worktree, every remaining command in this
  child plan runs from that worktree. Before each mutating task, assert its
  canonical root, branch, clean state, and expected predecessor commit.
- Shell-local `cd` and variables do not survive command calls or fresh workers.
  Task 1 records the canonical absolute worktree path and bridge SHA in the
  implementation handoff. Every later task receives both values explicitly,
  sets its tool working directory to that absolute path, and performs the root,
  branch, clean-state, and exact predecessor-SHA assertions in the same command
  invocation as its first mutation. A worker missing either value must stop.

**Interfaces:**

- Consumes: logical trigger, provider retry loop, upstream critical-agent policy.
- Produces: one iteration increment per trigger and one cluster-scoped
  `ClusterTerminalCoordinator` for artifact-capable workflows. Its fixed
  interface is `begin(executionKey, reason): TerminalExecutionClaim`,
  `markArtifactReady(receipt)`, `acceptArtifact(receipt)`,
  `commitArtifact(receipt)`, `succeed(message)`, `fail(reason)`, and
  `cancel(reason)`; later artifact code may use the generic
  `enterHandoffPending(receipt)`/`completeHandoff(key, message)` transitions.
  Every transition is idempotent and durably keyed.

`TerminalExecutionClaim` is a closed disposition carrying
`state: 'claimed' | 'reused' | 'terminal'`, the exact execution key, absolute
deadline, and the coordinator-owned read-only abort `signal`. `begin` atomically
links the caller's durable workflow-runtime claim to this terminal key. Final
operation code must receive this exact signal; no second `AbortController` may
represent terminal synthesis.

- [ ] **Step 5: Add bounded synthesis and idempotent terminalization**

Implement `ClusterTerminalCoordinator` as an opt-in primitive in the named
module. Expose an orchestrator installation/factory seam, but do not inspect
configuration, artifacts, or PR mode in this task: those concepts are defined
and attach the coordinator only in the later workflow-pack plan. When no later
caller installs one, every upstream generic lifecycle path is unchanged. An
installed coordinator owns the single deadline timer,
`AbortController`, durable phase/idempotency state, and publisher. The persisted
state machine is `RUNNING -> SYNTHESIZING -> ARTIFACT_READY`, followed by
`ARTIFACT_ACCEPTED|ARTIFACT_COMMITTED -> TERMINAL` without delivery or
`ARTIFACT_ACCEPTED|ARTIFACT_COMMITTED -> HANDOFF_PENDING -> TERMINAL` with it;
resume rehydrates it before
replaying effects. `begin` is the only entry to synthesis. Deadline/cancel abort
the signal and call `fail`; all completion methods clear the timer, reject late
results, and publish exactly one terminal message.

Add a `workflow_state` table in the same SQLite database, keyed by
`(cluster_id, workflow_instance_id, state_key)`, with schema version, CAS
revision, phase, bounded state JSON, and update time. Implement one ledger-owned
`transitionWorkflowState` transaction that compare-and-set updates this row and,
when supplied, inserts a deterministic message into the existing `messages`
table using its unchanged v6.46 schema. Semantic/input/output digests live in
the bounded `workflow_state.state_json` and are compared there on reuse; do not
add columns to `messages`. `CREATE TABLE IF NOT EXISTS workflow_state` runs
before new prepared statements, so an existing v6.46 ledger upgrades
idempotently without rewriting old messages. It returns `inserted`, `reused`, or
`conflict`; ordinary `MessageBus` publication emits only newly inserted rows
after commit. Workflow state records pending/delivered outbox disposition.
Startup/resume may explicitly re-deliver a committed pending row; live delivery
is therefore at-least-once across crashes and every consumer must be idempotent,
while the ledger contains exactly one deterministic event. Durable message rows
are the outbox—do not add a second outbox table.

Persist terminal execution key, phase, start time, absolute deadline, artifact
ID/sequence/checksum, handoff key when present, and the complete deterministic
terminal envelope/digests in that transaction. A winning terminal transition
and its `CLUSTER_COMPLETE`/`CLUSTER_FAILED` row therefore commit atomically.
Startup/resume re-delivers an existing durable row when live delivery was
interrupted; consumers are idempotent by deterministic message/execution key.
On resume,
an expired `SYNTHESIZING` record transitions once to failure; an unexpired one
re-arms only the remaining absolute duration and may re-invoke the deterministic
operation under the same execution key and frozen input cursor. Never restart a
full deadline or invent a new execution key after recovery.

Provide a routing facade for a later installed coordinator so every relevant
`CLUSTER_COMPLETE`/`CLUSTER_FAILED` publisher can use the same authority,
including `stop_cluster`, max
iteration, provider-terminal failure, subcluster failure, orchestrator fatal
paths, cancellation, and later artifact acceptance/commit. Generic upstream
agents/clusters retain upstream behavior. Add cross-agent/orchestrator race
tests, not only repeated calls from one lifecycle. Never install a ten-minute
cluster-wide timer.

Add crash tests after state mutation/before message insertion (the transaction
rolls back), after commit/before live delivery, and after delivery/before
shutdown. Each recovery observes one durable terminal row and one effective
terminal disposition.
Add an existing-v6.46-database fixture proving old messages still deserialize,
the new table is added once, and digest-checked state/message insertion works
after in-place upgrade.
