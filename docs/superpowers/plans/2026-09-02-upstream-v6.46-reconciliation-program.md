# Upstream v6.46 Reconciliation Program Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconcile the internal fork onto upstream v6.46.0, restore the approved fork products safely, and deliver telemetry and prompt-format follow-ups as independent branches.

**Architecture:** A history-only `ours` bridge makes the fork and upstream tips ancestors of an upstream-identical tree. Five dependency-ordered child plans then implement reconciliation foundations, preflight and owned operations, specialized workflow packs, provider-hook telemetry, and mechanical prompt JSON minification.

**Tech Stack:** Git worktrees, Node.js 22, TypeScript/CommonJS, Mocha/Node test runner, JSON workflow templates, GitHub Actions, Rust/Cargo, Python packaging.

**Spec:** `docs/superpowers/specs/2026-09-02-upstream-v6.46-reconciliation-design.md`

## Global Constraints

- Pin upstream to `e73727662df53bbaf8aad8ba9e489d2c76a79499` and fork history to `1bc71f6881da82de9f28dc5c78107a9151ed24c0`.
- The bridge must be `79` ahead and `0` behind; the reconciled result must be `79 + N` ahead and `0` behind.
- Use maintained TypeScript sources and regenerate owned artifacts; never hand-edit generated output.
- Keep the Node CLI active and the Rust/native product latent.
- Never run a live provider, push, merge to shared `main`, publish, or activate release credentials without separate user authority.
- Treat required handoff gates as non-bypassable.
- Keep telemetry and prompt minification out of the reconciliation branch; branch each from the accepted reconciled baseline.
