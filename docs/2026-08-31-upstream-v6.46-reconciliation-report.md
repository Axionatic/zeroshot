## Result

This is a two-tip reconciliation from a shared base, not a rebase or
cherry-pick series:

    shared base:        3077e37  v6.2.0
    fork main:          1bc71f6  (78 commits unique after the base)
    canonical upstream: e737276  v6.46.0 (146 commits unique after the base)

The recommended final graph keeps existing fork history and creates a normal
two-parent integration merge containing both `1bc71f6` and `e737276`. That
makes the upstream tip an ancestor of fork main, the Git condition for zero
behind. PR 31's four source commits remain useful prior art, but its squash
commit is the only one of those five commits reachable from fork `main`; they
must not be merged a second time.

An integration merge with no adaptation commits produces zero behind and 79
ahead: 78 existing fork-only commits plus one integration merge. The
reviewable target is therefore `0 behind, 79 + N ahead`, where `N` is the
number of reviewed adaptation and review-fix commits created on the
reconciliation branch. The exact `N` must be recorded at cutover.

## Safe topology and cutover

At execution time use the using-git-worktrees skill: detect existing isolation
first; if none exists, obtain consent and create a verified ignored worktree.
Do not alter the current checkout or shared main during reconciliation.

    git fetch --prune origin
    git fetch upstream main

    git rev-parse origin/main
    git rev-parse upstream/main
    git merge-base --all origin/main upstream/main
    git rev-list --left-right --count origin/main...upstream/main
    # Required pinned checkpoint: 1bc71f6, e737276, 3077e37, and 78 146.

    git branch backup/pre-v6.46-main 1bc71f6881da82de9f28dc5c78107a9151ed24c0
    git worktree add -b reconcile/upstream-v6.46 \
      ../zeroshot-v6.46-reconcile e73727662df53bbaf8aad8ba9e489d2c76a79499

Root the worktree at upstream v6.46 and create an explicit history-only bridge
to the pinned fork tip. The `ours` merge strategy is deliberate: it makes the
fork history reachable while proving that the initial reconciled tree is
byte-for-byte upstream, preventing silent auto-merges of obsolete fork code.
Approved behaviour is then reimplemented as reviewed adaptation commits:

    git merge --no-ff --strategy=ours \
      1bc71f6881da82de9f28dc5c78107a9151ed24c0 \
      -m "merge: bridge internal fork history onto upstream v6.46.0"
    git diff --exit-code e73727662df53bbaf8aad8ba9e489d2c76a79499 HEAD
    git merge-base --is-ancestor upstream/main HEAD
    git merge-base --is-ancestor 1bc71f6881da82de9f28dc5c78107a9151ed24c0 HEAD
    git rev-list --left-right --count HEAD...upstream/main
    # Immediately after the bridge: 79 0. After adaptations: (79 + N) 0.

This bridge preserves both ancestries without treating old patches as current
code. A squash-only migration can yield a similar tree but fails the ancestry
requirement. Do not push, merge to shared main, publish, or enable release
secrets without separate authority.

### 3. Replace fork command/quality-gate mechanics safely

Fork commits d4f2ead, e39a8f1, and 528ea6c run template-configured shell
commands. Do not restore that trigger action. Split its historical uses across
two owned boundaries:

1. The Node preflight gate discovers deterministic repository commands,
   requires one-time approval for a new or changed command, caches the approved
   command by repository, and runs before any provider call. Non-interactive
   runs execute an approved cached command; a narrow flag permits a missing
   cached gate, while `--skip-quality-gate` remains the broader compatibility
   opt-out. Neither flag affects `requiredQualityGates` at handoff.
2. Review report formatting, document reconstruction/assembly, and revision
   context construction become typed, in-process operations. They consume
   validated message/ledger data, publish explicit success or failure events,
   and never expose a template-controlled command, shell, subprocess, or
   environment-variable protocol.

LLM-assisted discovery may suggest a command for human confirmation but never
authorizes or executes it. Gate execution needs a contained repository cwd,
bounded environment/time/output, redaction, cancellation, cache invalidation,
and foreground/detached/worker parity. Protected handoff gates remain
upstream-owned and non-bypassable.

### 4. Rebuild workflow packs one family at a time

Current upstream lacks the fork's code-review, docs-review, and document-draft
families. Port them as optional products in this order:

1. Shared template parameters/defaults and topic-contract corrections.
2. Code-review base plus Bell/Book/Candle/conductor.
3. Docs-review base plus Trace/Vector/Axiom/conductor.
4. Doc-draft base plus Facet/Lens/Prism/conductor, reconstruction, assembly,
   revision, and delta/iteration contracts.
5. Typed preflight-option propagation for both approved compatibility flags.

Each family needs schema, topology, random/simulation, zero-findings, retry,
max-iteration, output, and failure-path coverage before the next family.
Upstream generic defaults stay in place.

### 5. Restore telemetry after reconciliation through owned overlays

Do not carry telemetry in the reconciliation merge. After the reconciled
baseline passes, create a dedicated feature branch and implement Claude and

1. Decide foreground-TTY capability once before provider launch; do not enable

2. Register provider-supported `SubagentStart`/`SubagentStop` hooks only in
   Zeroshot-owned per-run Claude and Codex configuration.
3. Normalize both providers into one bounded lifecycle-event sink and existing

4. Use spawn-time `description`/`task_name` only when hook data correlates it
   safely to a child ID. Fall back to provider agent type; never inspect
   transcripts or restore PR 31's Codex JSON-stream observer.
5. Bound reads, reject unsafe paths/records, clean up only owned files, and
   cover packaging, disabled-hook, unsupported-version, concurrency, and

Never write user settings, copy arbitrary user hook shapes, follow unsafe
paths, bypass unrelated hook trust, or silently replace malformed

When decisions are settled, write a design/spec, then invoke writing-plans to
make tasks with exact files, tests, interfaces, upstream SHA, chosen

finding against the actual branch before changing code; fix critical/important

## Completion criteria

Fresh verification must prove:

1. `upstream/main` at pinned v6.46 is an ancestor of final HEAD.
2. `git rev-list --left-right --count HEAD...upstream/main` reports
   actual-ahead 0, and ahead count matches the declared 79-plus-task-commit
   accounting.
3. The final diff from e737276 matches an approved customization manifest:
   no unexplained upstream deletions, generated drift, or identity mismatch.
4. Every fork commit has an evidence-backed disposition and retained behaviour
   has a current regression test.
5. Selected Node, protocol, Rust, Python, packaging, and release checks pass;
   no live provider or zeroshot run occurs without explicit permission.
