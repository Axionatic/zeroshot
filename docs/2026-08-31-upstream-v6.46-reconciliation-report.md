## Safe topology and cutover

At execution time use the using-git-worktrees skill: detect existing isolation
first; if none exists, obtain consent and create a verified ignored worktree.
Do not alter the current checkout or shared main during reconciliation.

    git fetch --prune origin
    git remote add canonical-upstream https://github.com/the-open-engine/zeroshot.git
    git fetch canonical-upstream refs/heads/main:refs/remotes/canonical-upstream/main

    git rev-parse origin/main
    git rev-parse canonical-upstream/main
    git merge-base --all origin/main canonical-upstream/main
    git rev-list --left-right --count origin/main...canonical-upstream/main
    # At the pinned checkpoint: c8fa688, e737276, 3077e37, and 77 146.

    git branch backup/pre-v6.46-main origin/main
    git branch backup/pre-v6.46-ship fix/ship-hook-scripts
    git worktree add -b reconcile/upstream-v6.46 ../zeroshot-v6.46-reconcile canonical-upstream/main

The reviewable path is preferable: root the worktree at upstream v6.46,
implement approved fork adaptations as reviewed commits, then bridge-merge the
full fork tip:

    git merge --no-ff 6cc79d68e5245815943ddb0ffbd76df4a363ba79 \
      -m "merge: integrate fork customizations with upstream v6.46.0"
    git merge-base --is-ancestor canonical-upstream/main HEAD
    git rev-list --left-right --count HEAD...canonical-upstream/main
    # Required: right side is 0; record actual left-side count.

This bridge merge preserves upstream ancestry and fork history while allowing
normal task commits beforehand. A squash migration can yield a similar tree
but will not make upstream an ancestor; it does not meet zero-behind. Do not
push, merge to shared main, publish, or enable release secrets without
separate authority.

## Plan and review process

When decisions are settled, write a design/spec, then invoke writing-plans to
make tasks with exact files, tests, interfaces, upstream SHA, chosen
identities, selected workflow scope, and N/ahead-count accounting. Execute
with subagent-driven-development in the isolated worktree: fresh implementer
per task, task review for plan compliance and quality, ledgered rulings/fix
rounds, and a whole-branch review before cutover. Verify every reviewer
finding against the actual branch before changing code; fix critical/important
issues or record a technical ruling.

## Completion criteria

Fresh verification must prove:

1. canonical-upstream/main is an ancestor of final HEAD.
2. git rev-list --left-right --count HEAD...canonical-upstream/main reports
   actual-ahead 0, and ahead count matches the declared 82-plus-task-commit
   accounting.
3. The final diff from e737276 matches an approved customization manifest:
   no unexplained upstream deletions, generated drift, or identity mismatch.
4. Every fork commit has an evidence-backed disposition and retained behaviour
   has a current regression test.
5. Selected Node, protocol, Rust, Python, packaging, and release checks pass;
   no live provider or zeroshot run occurs without explicit permission.
6. Final whole-branch review has no unresolved critical or important finding.
